🌐 last30days · 一张图看懂它在干嘛

问「最近 30 天，真实的人怎么说」

/last30days 是一个 AI 智能体技能：给它一个主题，它会去 Reddit、X、YouTube、 Hacker News、Polymarket 等地方，把最近一个月真实用户的讨论和热度捞回来， 再综合成一份有出处、可查证的摘要。

🗣️ 看的是「人」，不是编辑 📊 用赞数 / 点赞 / 真金白银排序 🔌 装进 Claude Code、Codex、Cursor… 🆓 没有 API key 也能跑

一句话

它跟普通搜索有什么不一样？

普通搜索给你的是网站和编辑挑出来的内容；/last30days 给你的是 最近 30 天里，一群真实的人用赞、评论、点赞、甚至下注真金白银「投票」出来的内容。

换句话说：它不问「哪个网站权威」，而是问「过去一个月，大家实际上在聊什么、聊得多热、态度怎样」。

它去哪里捞

为什么 Polymarket 也算一个来源？ 因为在预测市场里，人们是拿钱投票—— 比起随口一句评论，「愿意押多少钱」往往更能反映大家真实相信什么。

它怎么运作

从「一句主题」到「一份摘要」的六步

  1. 拆问题：把你的主题换成几种不同问法（技术上叫「子查询」），避免只用一种说法漏掉内容。
  2. 并行开查：每个来源同时查（用多线程），不是一个查完再查下一个，所以快。
  3. 富化：这是它的招牌动作——搜到 Reddit 帖子后，真的再去 Reddit 抓一次拿到真实赞数、评论数、热门评论，而不是让 AI 猜。
  4. 合并去重：同一条内容可能被好几条子查询各搜到一次，按「归一化后的网址」合成一条，并保留信息最全的那份。
  5. 过滤打分：先确认这条内容真的在讲你的主题（实体核对），再按热度打分、聚类。
  6. 合成：最后把这些证据写成一段有结论、有关键规律、有脚注出处的摘要交给你。

怎么排序

热度说话，但要先「真的在讲这件事」

排序的燃料是真实互动：赞数、评论数、点赞、观看、下注金额。但在比热度之前，有一道关卡——

🎯 先过「实体核对」这一关

搜「英伟达财报」时，一条讲别的公司、只是热度很高的帖子会被果断降权， 热度再高也救不回来。判断时只看主题的核心词（第一个词）， 因为后面的「财报」「测评」这类词通常只是描述你想知道什么，硬要求全部命中反而会错杀真正相关的内容。

🏆 再看谁被讨论得最凶

过关之后才比热度。当月被讨论最多、最有共识的内容排在前面； 它还会特意保留几个「高互动又切题」的名额， 确保那种「大家都在转但标题跟你搜的词对不太上」的爆帖，也能进到结果里。

招牌动作

「富化」：数据是抓来的，不是猜的

很多 AI 工具会让模型「估计」一个帖子大概多热。这个技能不这样——它搜到 Reddit 帖子后， 会免费再打一次 Reddit 的公开接口，把那条帖子的真实数据抓回来：

为什么这很重要？ 因为它排序、判断「哪条最值得看」全靠这些真实数字。 数字若是猜的，排序就是假的；数字是抓的，结论才站得住。

要不要花钱

没有 API key 也能用，有 key 更强

它设计成「零门槛先能跑，愿意配 key 再升级」。两种模式都合法：

🆓 免 key 模式🔑 配了 key 的模式
怎么拿数据靠公开网页抓取 + RSS 订阅用官方认证接口（OpenAI / xAI 等）
怎么排序本地打分（词面 + 真实互动）可用大模型帮忙判断相关性、重排
切题把关更依赖「实体核对」这类规则来防跑题模型能从语义上判断是否相关
成本零按各家接口计费
技能里还内建一个 doctor 体检命令：它会先告诉你哪些来源现在能用、哪些因为缺 key 或登录会被跳过， 跑之前先心里有数，而不是跑完才发现某个平台是空的。

进阶玩法

Discovery：不给主题，让它告诉你「该研究什么」

前面讲的都是「你给主题、它去查」。还有一个反过来的模式——你什么都不给， 它自己去各大平台的热榜里扫一圈，帮你找出「最近有什么值得研究的趋势」。

诚实的空结果也是一种结果。 如果这轮没有任何话题够格，它会直接说「没有」， 并指出最接近的那个弱信号——不编、不凑、不硬给你一个假趋势。这是这个项目很看重的一条原则。

一个有意思的细节

为什么它的说明书有 1400 多行？

这个技能由两部分组成：一份 SKILL.md（写给 AI 看的「行为契约」）+ 一个 Python 引擎（真正干活的代码）。 让人意外的是，那份说明书非常长、非常啰嗦——这不是啰嗦，是刻意的。

🧩 引擎 = 干活的手

scripts/last30days.py 负责真正去查、去抓、去打分。 AI 只要按约定传对参数，引擎就吐出固定格式的结果。

📜 SKILL.md = 给 AI 的紧箍咒

它规定 AI 拿到结果后只能怎么呈现： 第一行必须打一个版本徽章、不许自己编标题、不许加小标题、不许在结尾附一堆链接……

为什么管这么死？因为作者真的踩过坑：同一个模型、内容差不多的说明书， 有一批测试里 AI 会「自由发挥」，把结果写成一篇博客、编出根本没搜到的标题。 于是这份契约用了好几个「结构锚点」——比如强制第一行输出徽章——把 AI 死死按在正确的格式上。

一句话总结： 这份超长说明书是在跟「AI 容易自作主张」这件事对着干。 它把「必须怎么做、绝对不许怎么做」写死，换来的是每次输出都长一个样、可预期、可信。 对做 AI 智能体的人来说，这本身就是个很好的范例。
