Provider endpoint overrides (`OPENAI_BASE_URL`, `XAI_BASE_URL`, `OPENROUTER_BASE_URL`) now refuse a cleartext remote target: an `http://` override to a non-loopback host is dropped with a stderr warning and the vendor endpoint is used instead, so a redirected request can no longer put the provider's bearer token on the wire unencrypted. `http://` on loopback still works for local gateways (LiteLLM, Ollama, SSH tunnels). `OPENROUTER_BASE_URL` was also missing from the `--preflight` endpoint-override report even though the engine propagates it, so an OpenRouter redirect was invisible in the pre-run permission summary; it is now reported alongside the other two.
