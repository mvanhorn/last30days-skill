`--github-user` no longer returns unrelated repos for people whose PR search comes back empty. GitHub answers `author:<login>` with HTTP 422 for accounts that are absent from its search index, and person mode read that as "no activity" and let the run backfill the topic from generic keyword search — so a user with 33 repos and an 811-star project pushed inside the window contributed nothing to the report. Person mode now falls back to a repos lane (`/users/{login}/repos?sort=pushed`, filtered on `pushed_at` within the window) when the PR search is empty or unavailable, and a pinned `--github-user` that still yields nothing is recorded as `no-results` instead of passing silently.
